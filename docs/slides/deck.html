TRADE-OFFS

Three design choices, and what each one cost

01

Seats in an actor, one request at a time

No seat is ever sold twice. The cost: requests wait their turn, so 300 at once took 8.5 seconds to clear.

02

Rules in my server, not in the AI's instructions

The AI can call any tool at any point, so my server checks every rule itself: fees, refunds, and whose booking can change.

03

A faster AI model

Each reply comes about a second sooner. The Mandarin desk kept the slower model, because the faster one slipped out of Mandarin.

WHAT BROKE

The worst bug: phone calls went silent, but chat tests kept passing

It took about 11 test calls to find.

1

What happened

On a phone call, the desk answered and then said nothing. Over text chat it worked, so every automated test passed.

2

How I tested

I set up a second AI that phones my desk. Each test call takes about a minute, and nobody has to dial in.

3

How I found it

I removed half of the conversation flow and called again, and kept going until one piece was left.

4

The cause

On calls, Telnyx turns each route between steps into a tool with the route's name. One name was too long and had a colon, so every reply failed.

5

The fix

Short route names, an automated check on every name, and a real test call after every change.

BUILDING ON TELNYX

Four things the platform taught me

01

Chat isn't a call

Calls turn workflow steps into tools; chat doesn't. Only a real call shows those bugs.

02

The webhook gets 1.2 seconds

Telnyx stops waiting after about 1.2 seconds, even with an 8-second timeout. I answer within 900 ms.

03

Tool calls ignore my step limits

Per-step tool limits don't apply to tool servers, so mine enforces them.

04

Mass shutdowns hurt

200 idle actors shutting down together crashed the actor host. My health check caught it.

HEALTHY VS UNHEALTHY

How I know it's working, and what happens when it isn't

01

A fake caller every minute

It calls the webhook and the tool server. A failure, or 90 s of silence, turns the light red.

02

One trace per call

One ID follows the call through every step, so I can see which hop failed and how long it took.

03

A switch to break it

"Break MCP" makes every tool fail. The light turns red, and calls fall back to a callback.

04

Fails safe

If the check for a free person fails, the caller gets a callback, never silence.

Q1 / ARCHITECTURE

Why does each piece of data live where it does?

I picked by who writes it and how often.

01

Seats: one actor per flight

It handles one request at a time, so it can't oversell.

02

The caller: one actor per call

The key-value store took over a second to read. An actor answers in milliseconds.

03

Settings: key-value store

Read on every call, changed rarely, flipped without a redeploy.

04

Bookings: SQL

It stands in for the airline's real reservation system.
